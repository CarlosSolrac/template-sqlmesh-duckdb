### ADR-0007: Build each run on a copy of the warehouse and swap it in only when the run succeeds
- Status: Accepted
- Date: 2026-10-22
- Context: Restating a `FULL` model rebuilds its prod table in place, so when an audit fails the table already holds the rows the audit rejected. For the staging model this was an accepted exception; for the mart it meant consumers could read rows a blocking audit rejected while the log said otherwise (reproduced on 2026-10-18 with SQLMesh 0.236.2: a day whose only order had no amount left `(2026-10-03, 1, NULL)` in the mart). The warehouse file also holds SQLMesh's state, so a copy of the file is a consistent copy of data and state. SQLMesh resolves `config.yaml`'s relative `database: data/warehouse.duckdb` against the process working directory, not against `Context(paths=...)`, so the working directory decides which file a run writes; this supersedes [ADR-0006](ADR-0006-run-in-the-project-directory.md), which ran in the project directory for the same reason.
- Decision: `main(project_dir=PROJECT_DIR)` resolves `project_dir` to an absolute path. `StagedWarehouse` copies `data/warehouse.duckdb` to `data/.build/data/warehouse.duckdb` before a run. The whole run (ingestion and both plans) works on the copy inside `contextlib.chdir(data/.build)`, where SQLMesh resolves the relative database to the copy, and SQLMesh is given the project as `Context(paths=<absolute project_dir>)`; `config.yaml` stays the only place that names the database. When every plan applied, the copy replaces the live file with one `os.replace`; otherwise the live file is not touched and the copy is kept as `data/warehouse.failed-<UTC timestamp>.duckdb`, so the rejected rows can be queried. The newest three failed copies are kept, and a successful run leaves them alone.
- Alternatives: restore a backup of the live file after a failure, rejected because the live file is modified during the run and a crash would leave it half built; run the plans in a SQLMesh dev environment first, rejected because SQLMesh cannot restate models whose current version is used in production outside prod; stage the mart in a second table that a final model swaps in, rejected because every mart would need the same pattern. From ADR-0006, still rejected: default `project_dir` to `Path.cwd()` like the `sqlmesh` CLI, because `uv run project` from a subfolder would then fail on a missing CSV; build SQLMesh's `Config` in Python with an absolute path, because it duplicates `config.yaml` and lets the CLI and `main()` diverge.
- Consequences: The live warehouse never holds rows an audit rejected, and a crashed run leaves it intact. Each run copies the whole file, which costs time and disk in proportion to its size; revisit with the volumes of [TODO.md](../../TODO.md) item 1. Rows that failed an audit are no longer queryable in the live warehouse, only in the failed copies; the fourth failure removes the oldest copy, and the copies take up to three times the warehouse size in disk. `uv run project` works from any directory; the working directory is process-global state for the length of the run, which is fine for a CLI entry point but not thread-safe. The end-to-end tests start in a directory outside the project copy, so removing the `chdir` makes them fail. `data/.build` and the failed copies are git-ignored with `data/`.
